01Overview toàn bộ dự án

Giải thích ngắn gọn — đọc xong phần này là hiểu dự án làm gì, cho ai, và đang ở giai đoạn nào.

Dự án là gì — nói đơn giản

Hình dung: bạn chơi Cờ Tướng trên mạng, nhưng không tự bấm quân. Bạn viết chương trình (bot) bằng JavaScript/TypeScript. Server ghép bot với bot (hoặc bot với người), cho chúng đánh nhau, rồi bạn xem lại trận như xem video — tua, pause, xem bot “suy nghĩ” gì trong log.

Algo-Xiangqi = sân chơi cho lập trình viên thi thuật toán qua Cờ Tướng: viết bot → đem bot đi đấu → leo bảng xếp hạng (Elo) → xem replay để cải thiện code.

Người chơi làm gì từng bước:

  1. Đăng ký / đăng nhập (email, Google, hoặc chơi thử guest)
  2. Viết bot trên trình soạn code web (Monaco Editor), lưu nhiều phiên bản (v1.0, v1.1…)
  3. Chọn một phiên bản làm “đại diện” (Active Bot) mang đi đấu mọi chế độ
  4. Chọn chế độ (Cờ Ngửa / Úp / Thế) và thể loại (xếp hạng, luyện tập, treo máy, đấu Boss…)
  5. Server tự chạy trận — bot của bạn nhận thế cờ, trả về nước đi trong thời gian giới hạn (500ms/lượt)
  6. Xem kết quả, replay trận, xem log bot in ra — rồi sửa code và thử lại

Hệ thống gồm những khối nào

Không cần nhớ tên kỹ thuật — chỉ cần hiểu ai làm việc gì:

Giao diện web (FE)

  • Nơi viết code bot
  • Nơi xem replay bàn cờ
  • Dashboard, bảng xếp hạng, hồ sơ, guild

Máy chủ (BE)

  • Ghép trận, tính Elo
  • Kiểm tra nước đi hợp lệ
  • Điều phối luồng chơi realtime

Sandbox (hộp cát)

  • Chạy code bot an toàn, tách biệt
  • Giới hạn CPU, RAM, thời gian
  • Chống bot chạy vô hạn hoặc phá hệ thống

Dữ liệu

  • Lưu bot, lịch sử trận (PGN/JSON)
  • Redis cache bảng xếp hạng
  • Chưa có database riêng — theo code nền hiện tại

Sản phẩm MVP sẽ có gì (đã chốt)

3 cách chơi cờ

  • Cờ Ngửa — thấy hết quân, thuần tính toán (như cờ bình thường)
  • Cờ Úp — quân úp, bot phải đoán và chấp nhận rủi ro
  • Cờ Thế — giải bài tập: đi N nước để thắng từ thế cho sẵn

5 kiểu thi đấu

  • 1v1 / 2v2 xếp hạng — có Elo, ghép đối thủ ngang tầm
  • Scrim — đấu thử, không mất điểm
  • Auto Fight — treo máy, server tự xếp trận khi bạn offline
  • Boss — 5 cấp độ, có thể sửa code ngay trong trận

Thêm: đăng ký + Google + guest · luật cờ Việt Nam phổ thông · bot chỉ JS/TS · mỗi lượt bot có tối đa 500ms · guild tạo/join tự do.

03Kinh nghiệm xương máu — bài học rút ra từ M1

Chốt có code hay không muộn một nhịp là rewrite cả gói. Docs là ý định, code là thực tế — lệch thì ghi conflict và hỏi, đừng tự “hòa giải” trong đầu.

Thiếu wireframe mà vẫn cố viết spec = bịa. Có markdown chưa Pass REVIEW = mới dừng ở bản nháp. Estimate từ function-list seed = số đẹp nhưng chưa ai dám ký.

Gom câu hỏi một lần, cập nhật tài liệu một lần — hỏi rời là artifact lệch. Giả định tạm phải hủy ngay khi đã có câu trả lời, kẻo doc cũ cãi doc mới.

BA không quyết hộ khi chưa được ủy quyền — làm rõ lựa chọn để đúng người quyết. Domain game cũ không phải bản đồ game mới: reverse UI Bomberman rồi gọi là Xiangqi là sai hướng ngay từ đầu.
